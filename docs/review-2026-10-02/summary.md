# 整体工程审查与改进方案

日期：2026-10-02。基线：GitHub `main` 最新提交 **`756179a`**。目标：在保留现有功能、硬件兼容和线协议的前提下，降低缺陷风险与迭代成本。

**结论：适合渐进修复和边界收敛，不适合整体重写。** 当前工程已经有端口、Transport、FlashCommandSet、PlatformOps、session、设置 descriptor 等抽象。主要问题是这些抽象没有统一约束操作所有权、资源恢复、bank 窗口和失败结果；继续增加层数或机械合并 GBA/MBC 不会自动改善这些问题。

用户本地修改完整保留在 `stash@{0}`（`codex-pre-sync-2026-10-02`），未纳入审查、未恢复、未删除。本轮只新增报告，没有修改业务代码、固件、依赖配置或测试。

## 优先处理的问题

| 优先级 | 问题 | 影响与证据 |
| --- | --- | --- |
| P0 | STM32 帧校验不足（FW-01） | 短写帧长度下溢、超大读响应越界，可导致内存损坏或非预期卡带写入；代码路径确认 |
| P1 | 取消提前解除独占（LC-01） | 旧任务未退出就允许新任务，旧 finally 可清理新 controller；原类内存复现 |
| P1 | 连接资源所有权丢失（LC-02/03/04） | 枚举失败清空活跃 handle、指定端口重连忽略 close failure、迟到 open 未回收；LC-02 原类内存复现 |
| P1 | bank / 包长不变量不完整（AD-01/02） | 非对齐读取或 RAM 写越窗口；模拟大块产生 16 位长度溢出的请求，模拟器却接受 |
| P1 | 固件等待与结果错误（FW-02～06） | 超时仍发成功、buffer=1 不推进、STC 分片/取消卡住、旧 C# 无界等响应 |
| P1 | RTC 状态和写后验证（AD-03/04） | 异常可能遗留 Halt；verify 只打印，不判定读回值与目标一致 |
| P1 | CI 未执行行为门禁（AR-01） | 打包通过不足以拦截这些回归；已有测试未成为 PR 必需质量检查 |

这些是条件触发的问题，不表示正常设备上的全部功能已经失效。硬件表现和修复验收仍需要实机，不能由单元测试替代。

## 设计改进方向

1. **设备级 operation owner。** 生命周期必须包括 running → cancelling → recovering → idle；进度、结果、finally 都绑定 token/generation。页面、RTC、PPB 和断连复用这一所有权。
2. **共享纯规则，保留硬件策略。** 抽出窗口分块规划、帧长度校验和地址单位转换；GBA/MBC/STM32/STC 各自保留 bank、总线时序和命令能力差异。
3. **结构化失败贯穿调用链。** 底层保留 code/stage/cause/地址/cleanupError，UI 最后翻译；逐步减少只转发的包装，避免来回把错误变成字符串。
4. **减少多份状态事实。** connection snapshot 是资源所有权源；Vue refs 是投影；操作上下文在开始时快照。查询失败不能销毁资源事实，取消请求不能冒充完成事实。
5. **验证驱动抽象收敛。** 删除没有实际调用的基类模板、迁移具体 read/verify 流程以前，先固定命令 transcript、golden bytes、进度和失败恢复行为。

4 月建议中的不少提取工作已经完成；本轮不重复推动常量、设置 getter 和多菜单拆分。7 月清单虽未更新，相关代码已经修复；应修正审查状态和 Electron 文档，避免后续 agent 按陈旧计划再次加工。

## 实施建议

按 [fixes-plan.md](./fixes-plan.md) 的六个批次执行：**行为基线与门禁 → 协议边界 → 生命周期恢复 → 地址规划与 RTC → 抽象收敛 → 文档和性能**。每个改动只处理一个行为边界，保持旧接口兼容，达到验收条件才移除旧实现。

“不破坏功能”不能由静态审查保证。方案用字节/事件级基线、失败注入和 STM32/STC × Web/Tauri 的实机回归矩阵来降低风险；没有硬件验收证据的批次不能标记功能完全兼容。

## 覆盖限制

不是每个函数的穷尽审计：重点追踪连接、取消、传输、ROM/RAM、RTC、LK、固件命令入口、旧客户端串口与 CI。第三方 HAL/USB 库、原理图、电气时序、每种 flash 手册、完整 C# mission、全部 UI/翻译/模拟器算法仅有轻量或间接覆盖。没有 E2E、真实设备压力测试和软件依赖安全扫描结论。
